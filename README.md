# Sway
Музыкальное веб-приложение для компьютеров и телефонов. HTML, CSS, JavaScript, Cloudflare Workers и D1. Установка из браузера (PWA); для стриминга требуется сеть.

Публичный адрес: https://tonika-music.905589xx.workers.dev

Имя Cloudflare Worker и базы D1 сохранено, чтобы не менять адрес проекта, аккаунты и коллекции.

## Запуск локально

```powershell
npm.cmd ci
npx.cmd wrangler d1 migrations apply tonika-music --local
npm.cmd run dev -- --port 8794 --var REQUIRE_YANDEX_LOGIN:0
npm.cmd test
```

С флагом `--var REQUIRE_YANDEX_LOGIN:0` можно тестировать приложение без аккаунта. Для проверки обязательного входа используйте `--var REQUIRE_YANDEX_LOGIN:1` с настроенными ключами Яндекс ID.

## Публикация

Каждое готовое изменение публикуется после проверки. База приложения указана в `wrangler.jsonc`. При переносе в другой Cloudflare-аккаунт создайте отдельную D1 через `npx wrangler d1 create tonika-music` и замените UUID. Перед выходом версии примените ожидающие миграции:

```powershell
npx.cmd wrangler d1 migrations apply tonika-music --remote
```

Пока секреты Яндекс ID не настроены и не проверены, сохраните гостевой доступ:

```powershell
npm.cmd run deploy -- --keep-vars --var REQUIRE_YANDEX_LOGIN:0
```

После проверки входа реальным аккаунтом обязательный вход можно включить командой `npm.cmd run deploy -- --keep-vars --var REQUIRE_YANDEX_LOGIN:1`.

После публикации запустите `node scripts/check-public.mjs https://tonika-music.905589xx.workers.dev`. В гостевом режиме он проверяет аудио каталога. При обязательном входе проверяет доступность приложения, редирект OAuth и защиту каталога. После включения обязательного входа проверьте реальный вход, воспроизведение, сохранение профиля и выход.

Скачанные записи находятся в «Коллекция → Скачанное» и хранятся в браузере на текущем устройстве. Приложение сохраняет полные записи Sway и поддерживаемые записи Commons с открытой лицензией. Внешние виджеты не скачиваются. В офлайне работают список скачанного, проигрывание и перемотка; профиль и поиск требуют подключения. Очистка данных сайта удаляет скачанные записи.

## Включение Яндекс ID

1. Зарегистрируйте веб-приложение в [Яндекс OAuth](https://oauth.yandex.ru/) по [документации](https://yandex.ru/dev/id/doc/ru/register-auth). Разрешите `login:info` и `login:avatar`. Sway запрашивает портрет как необязательное разрешение и показывает его в личном профиле, если пользователь ещё не загрузил своё фото. В профиле по ссылке видны только фото, загруженные в Sway.
2. В Redirect URI укажите `https://tonika-music.905589xx.workers.dev/auth/yandex/callback` (точное совпадение с адресом приложения). Для локального входа можно отдельно добавить `http://127.0.0.1:8794/auth/yandex/callback`.
3. В **Variables and Secrets** существующего Worker добавьте `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` как secrets. Через CLI: `npx.cmd wrangler secret put YANDEX_CLIENT_ID --name tonika-music` и `npx.cmd wrangler secret put YANDEX_CLIENT_SECRET --name tonika-music`. Локальные значения храните в игнорируемом файле `.dev.vars`.
4. При использовании одного публичного домена задайте `PUBLIC_ORIGIN` равным этому origin без завершающего слеша. Откройте `/api/health`: `loginConfigured: true` означает, что переменные найдены. Проверьте вход и выход реальным тестовым аккаунтом. Параметр `loginConfigured` не проверяет действительность ключей.
5. Для админ-панели задайте секреты через `wrangler secret put`. `ADMIN_SETUP_TOKEN` (не короче 16 символов) требуется только для первой установки пароля: `POST /api/admin/setup` с заголовком `X-Admin-Setup-Token`; после установки секрет можно удалить. `TELEGRAM_WEBHOOK_SECRET` обязателен для `/api/telegram/webhook` — передайте его в `setWebhook` как `secret_token`. `ADMIN_TELEGRAM_CHAT_ID` ограничивает бота одним чатом. Пароли администратора хранятся как PBKDF2-SHA256 с солью.
6. Примените миграции: `npx.cmd wrangler d1 migrations apply tonika-music --remote`. Проверка всех миграций на чистой базе: `npm run check:migrations`.

Когда обязательный вход включён, для плеера нужен аккаунт Яндекс ID. Имя, ник, описание, аватар, обложка, песня профиля, настройки и избранное из каталога Sway сохраняются в D1. Профиль закрыт по умолчанию; после включения доступа по ссылке его видят вошедшие слушатели. Таблица `subscriptions` подготовлена для будущих тарифов, оплаты пока нет. «Моя волна» учитывает лайки, прослушивания и ранние пропуски. История хранится в браузере этого устройства; запрос открытых записей передаётся Wikimedia Commons.

## Музыка

В `public/catalog.json` сейчас 7000 записей. Открытые лицензии (CC BY, CC BY-SA, CC0) подтверждены только для части каталога и для слоя Wikimedia Commons; для остальных записей права нужно проверить — см. `LEGAL.md`. Авторство и лицензии доступны в меню трека, в пункте «Источник и лицензия». При добавлении записей убедитесь, что лицензия покрывает публичный стриминг, сохраните ссылку на условия и положите разрешённый файл в `public/media`.

Поиск объединяет каталог Sway и открытые записи Wikimedia Commons. Лицензия и исходная страница Commons доступны в карточке записи; избранное Commons хранится на устройстве. Плеер показывает результаты в форматах, которые браузер может воспроизвести. Расширенный каталог не требует платного ключа.

Для треков, альбомов и публичных плейлистов Яндекс Музыки вставьте ссылку или официальный код «Поделиться → HTML-код» в поиск. Доступность определяет виджет Яндекс Музыки. Если он недоступен, есть ссылка на оригинал. Яндекс ID отвечает за вход в Sway, сессия не даёт Sway доступа к подписке Плюс.

На iPhone запустите трек из Sway или Commons, затем заблокируйте экран. Плеер передаёт обложку, позицию и команды в системную Media Session. Появление карточки и Dynamic Island зависит от iOS и модели устройства. Громкость на iPhone задают кнопки устройства, треки играют последовательно. Эквалайзер Sway включает Web Audio после касания. Если браузер не запускает обработку, плеер использует системный звук; если после прерывания iOS блокирует автоматическое продолжение, нажмите «Воспроизвести». В поддерживаемых браузерах Sway заранее буферизует следующую запись. При автопереходе плеер смешивает до десяти последних секунд с началом следующего трека, когда данные уже готовы. Плеер Яндекса сам управляет звуком из своего виджета.

Команда `npm run art` пересобирает SVG, значки и PNG для системного плеера. После добавления треков или изменения обложек запустите `node scripts/cover-colors.mjs` и `node scripts/icons.mjs`. Проверка `npm test` использует Microsoft Edge (переменной `TONIKA_BROWSER=chrome` можно выбрать Chrome).

После добавления или замены аудиофайлов запустите `node scripts/wave-pulses.mjs`. Он обновит `public/wave-pulses.json` по акцентам в аудио, чтобы волна реагировала на музыку и сохраняла синхронизацию при перемотке.

Проверка серверных сценариев на изолированной SQLite с имитацией ответов Яндекс ID: npm run test:accounts.

Проверка поиска, реального аудио Commons и управления через Media Session: `npm run test:sources`. Переменные `SWAY_WEBKIT=1` и `SWAY_VERIFY_WIDGET=1` добавляют WebKit с профилем iPhone и проверку публичных виджетов.

Проверка эквалайзера: `node scripts/check-equalizer.mjs`. Она измеряет эффект пресета на тестовом звуке в Edge и проверяет восстановление обычного звука с профилем iPhone. Сборка WebKit для Windows проверяет доступные возможности браузера; проверка блокировки экрана требует iPhone.

В полноэкранном плеере фон строится из обложки текущего трека. На телефоне короткий свайп показывает соседнюю обложку и возвращает текущую, если трек не переключён. `node scripts/check-player-scene.mjs` проверяет свайпы, смену звука и фона, кнопки на компьютере и режим уменьшенного движения.
